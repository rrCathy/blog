这是我博客的第一篇技术记录——写的就是**这个博客自己**怎么跑起来的。结论先行：整套东西不花一分钱服务器费用，写文章 = 改一个 Markdown 文件然后 push。

## 为什么不用服务器

我的两个项目（GroupViz、grouplo）都已经是静态站点，托管在 GitHub Pages 上，由各自的源码仓库通过 Actions 自动构建、发布到 `rrcathy.github.io` 的子目录。博客天然也是静态内容 + 少量交互，完全可以复用这条管线，于是没有买服务器的必要。

## 站点架构

博客是一个 **Astro + React** 工程，独立源码仓库，内容与部署分离：

```text
rrCathy/blog (源码仓库，只管写文章)
 ├─ src/content/blog/   ← 文章：*.md（纯文本） / *.mdx（数学·交互）
 ├─ src/components/     ← React 交互组件
 └─ .github/workflows/  ← 构建 + 发布
        │   build (astro build)
        ▼
rrcathy.github.io (Pages 仓库)
 └─ blog/               ← 构建产物，托管在 https://rrcathy.github.io/blog/
```

文章写成 Markdown/MDX 就够了。技术文用普通 `.md`，数学文用 `.mdx`——里面可以直接内嵌 [@groupviz/react](https://github.com/rrCathy/GroupViz) 的交互组件，公式由 KaTeX 渲染。写作与发布分离：**日常写 `.md`，需要活插图才写 `.mdx`**。

## 发布管线

核心是一个 GitHub Actions 工作流，完全复刻 GroupViz 的做法：先 `astro build`，再把产物整体替换进 Pages 仓库的 `blog/` 目录并提交。

```yaml
name: Deploy blog

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run build          # 产出 dist/
      # …… checkout rrcathy.github.io → 替换 blog/ → commit & push
```

关键点是 GitHub 没有买服务器也替我们免费跑构建；而 `rrcathy.github.io` 仓库只存放最终产物，所以站点响应就是纯静态文件，速度与稳定性都有保障。

## 给未来的自己

维护时只需要记住三条：

1. 新文章 = 在 `src/content/blog/` 下新建 `.md` 或 `.mdx`，头部填 `title` / `pubDate` / `tags`；
2. 本地预览：`npm run dev`；发布前 `npm run build` 自查；
3. 写数学文章时，交互插图用 `<GroupScene symbol="A4" view="cycle" />` 这种声明式组件，其余交给我。
